# CAPSkip: Cancellation-Aware Prefix Skipping for Selective Backpropagation

Heejin Choi Yonsei University Sooil Development NCreate heejin.share@gmail.com

## Abstract

Per-step selective back-propagation forwards every example of a mini-batch but backpropagates only some of them. Most rules rank examples by loss or gradient magnitude, but such scalar scores ignore cancellation between per-example gradients: the gradient removed by a set can be much smaller than its individual magnitudes suggest. We introduce CAPSkip (Cancellation-Aware Prefix Skipping). Among the examples the model already classifies correctly, CAPSkip skips the longest prefix, in increasing order of last-layer gradient norm, whose vector sum stays within a relative budget b of the batch’s last-layer gradient. In exact arithmetic this bounds the change of the raw final-layer gradient, using rank-one contributions already avail able from the forward pass; the bound does not extend to deeper layers, optimizer updates, or the training trajectory. Because the cumulative distortion is not monotone in the prefix length, CAPSkip scans all prefixes; a factorised Gram matrix makes the scan cheap and keeps it on the device. With activation reuse and selected-row backward, CAPSkip fine-tunes DeiT-S on CIFAR-100 for 103 epochs in 0.576× the time of 103-epoch dense training, and is +0.25 pp [+0.08, +0.42] above an approximately time-matched 59-epoch dense run (n = 3).

## 1 Introduction

A common way to cut the cost of training is to spend less computation on examples that contribute little to the update. Per-step methods decide inside each mini-batch: they forward all B rows, score them, and back-propagate only a subset [9, 10, 13]. Per-epoch methods such as InfoBatch [19] and KAKURENBO [16] decide before the forward, from scores stored in earlier epochs, and save both passes. Common rules in both families score examples individually by loss or gradient magnitude. The quantity that matters for the update, however, is the sum of the skipped gradients. Perexample gradients of correctly classified examples can be small without being aligned, and their sum can be much smaller than the sum of their norms, so a magnitude-based score misjudges how much of the update is actually removed.

This paper studies a selection rule that measures the skipped gradient directly, in the one place where it is exactly and cheaply available: the final afine layer. For cross-entropy, the gradient of example i’s loss with respect to the final layer’s weights and bias is the outer product of the logit residual $h _ { i }$ and the augmented penultimate feature [ϕ<sub>i</sub>, 1]. Both factors are by-products of the forward pass. We sort the currently-correct examples by the norm of this outer product and skip the largest number $k ^ { * }$ of them whose summed contribution has relative norm at most b. Because summed vectors cancel, the relative distortion of a prefix is not monotone in its length; stopping at the first prefix that violates the budget under-selects, and magnitude-sum budgets are only conservative suficient conditions.

## Contributions.

1. An ideal cancellation-aware selection rule (CAPSkip) with an exact-arithmetic per-step bound on the raw last-layer gradient, a full-prefix scan that returns the maximal feasible prefix of the chosen order, and a worked example of why first-violation stopping and magnitude budgets select less (§2).

2. A device-only implementation: all prefix norms come from a 2-D cumulative sum of a factorised Gram matrix $( h _ { i } \cdot h _ { j } ) ( \phi _ { i } \cdot \phi _ { j } + 1 )$ , without materialising per-example gradients for the Gram calculation or synchronising the selector with the host (§3).

3. A weighted form for composition with outer re-weighting pruners, with a counter-example showing that the unweighted rule can violate the budget on the weighted raw gradient (§2.4).

4. An empirical study with pre-registered decision rules and deliberately narrow claims: an approximately time-matched accuracy gain in one fine-tuning task, an unresolved diference in from-scratch training, a mixed result for composition with InfoBatch, a learning-rate confound we measure explicitly, and the measured cost of executing the rule with and without activation reuse (§4).

## 2 Method

## 2.1 Setting and last-layer contributions

Consider a classifier with logits $z _ { i } = W \phi _ { i } + c \in \mathbb { R } ^ { C }$ , where $\phi _ { i } \in \mathbb { R } ^ { F }$ is the penultimate feature of example i, and a mini-batch of B rows trained with the mean loss $\begin{array} { r } { L = \frac { 1 } { B } \sum _ { i = 1 } ^ { B } \ell _ { i } , \ell _ { i } = \mathrm { C E } ( z _ { i } , t _ { i } ) } \end{array}$ with a (possibly label-smoothed) target $t _ { i } .$ . Write $\tilde { \phi } _ { i } = [ \phi _ { i } ; 1 ]$ and $\tilde { W } = \left[ W \ c \right]$ . The exact perexample gradient of $\ell _ { i } / B$ with respect to W<sup>˜</sup> is

$$
\begin{array} { r } { P _ { i } \ = \ h _ { i } \tilde { \phi } _ { i } ^ { \top } , \qquad h _ { i } = \frac { 1 } { B } \big ( \mathrm { s o f t m a x } ( z _ { i } ) - t _ { i } \big ) , \qquad \| P _ { i } \| _ { F } = \| h _ { i } \| \| \tilde { \phi } _ { i } \| . } \end{array}\tag{1}
$$

The full last-layer gradient is $\begin{array} { r } { V _ { 0 } = \sum _ { i = 1 } ^ { B } P _ { i } } \end{array}$ . If a set D of rows is removed from the backward, the selected objective $\textstyle { \frac { 1 } { B } } \sum _ { i \not \in D } \ell _ { i }$ has last-layer gradient exactly $\textstyle V _ { 0 } - \sum _ { i \in D } P _ { i }$ (the normalisation stays $1 / B )$ . The decomposition requires only that $h _ { i }$ and $\phi _ { i }$ be computed by the forward pass; the models used here (GroupNorm ResNet, LayerNorm ViT) have no cross-example coupling, so per-example gradients are also well defined for deeper layers.

## 2.2 The selection rule

Definition 1 (CAPSkip). Let $\mathcal { C } = \{ i : \arg \operatorname* { m a x } _ { c } z _ { i c } = y _ { i } \}$ be the rows the model currently classifies correctly, $m = | \boldsymbol { \mathcal { C } } |$ . Order them by $\| P _ { i } \|$ ascending, $\pi _ { 1 } , \ldots , \pi _ { m } .$ , and let $\begin{array} { r } { S _ { k } = \sum _ { i = 1 } ^ { k } P _ { \pi _ { j } } \ ( S _ { 0 } = 0 ) } \end{array}$ For $\| V _ { 0 } \| _ { F } > 0$ , define $D _ { k } = \| S _ { k } \| _ { F } / \| V _ { 0 } \| _ { F }$ . If $V _ { 0 } = 0$ , define $D _ { k } = 0$ when $S _ { k } = \mathrm { \dot { 0 } }$ and $D _ { k } = + \infty$ otherwise, so only zero-sum prefixes are feasible. For a budget $b \geq 0 .$ , CAPSkip drops the rows $\pi _ { 1 } , \ldots , \pi _ { k ^ { * } }$ from the backward, where

$$
k ^ { * } = \operatorname* { m a x } \{ k \in \{ 0 , 1 , \ldots , m \} : D _ { k } \leq b \} .\tag{2}
$$

The maximum in (2) is taken over all prefixes (a full scan), not up to the first k with $D _ { k } > b$ . The main comparisons use $b = 0 . 0 9 ;$ it was selected on validation data in the from-scratch CIFAR-100 setting and transferred unchanged to fine-tuning. Algorithm 1 gives the practical epsilon-relaxed implementation, whose distinction from this ideal definition is stated below.

## 2.3 Properties

The propositions below concern the ideal rule in Definition 1, exact arithmetic, and the raw finalafine-layer gradient before clipping or optimization.

Proposition 1 (Existence and exact last-layer bound). $k ^ { * }$ always exists, since $D _ { 0 } = 0 \leq b$ . Removing the prefix changes the raw final-layer gradient by $\Delta = - S _ { k ^ { * } }$ , with $\| \Delta \| _ { F } \le b \| V _ { 0 } \| _ { F }$ . For $V _ { 0 } \neq 0$ this gives $\| \Delta \| _ { F } / \| V _ { 0 } \| _ { F } = D _ { k ^ { * } } \leq b ;$ if also $b < 1$ , the angle between the dense and selected gradients is at most arcsin b. For $V _ { 0 } = 0$ , the selected gradient remains zero and its angle is undefined.

Proof. Immediate from $V _ { 0 } - ( V _ { 0 } - S _ { k ^ { * } } ) = S _ { k ^ { * } }$ ∗ and (2). For the angle, the set $\{ V _ { 0 } + \Delta : \| \Delta \| \le b \| V _ { 0 } \| \}$ is a ball of radius $b \Vert V _ { 0 } \Vert$ around $V _ { 0 }$ , seen from the origin under half-angle arcsin b. □

This is an exact-arithmetic statement about the ideal rule: $P _ { i }$ is the true per-example last-layer gradient. It says nothing about the gradients of deeper layers, which can change by more or less than $b ,$ and nothing about the optimisation trajectory over many steps.

Proposition 2 (Full scan versus first violation). Let $k _ { \mathrm { f v } } = \operatorname* { m i n } \{ k \in \{ 0 , \ldots , m - 1 \} : D _ { k + 1 } > b \}$ 2 with $k _ { \mathrm { f v } } = m \ i f$ no prefix violates the budget. Then $k _ { \mathrm { f v } } ~ \le ~ k ^ { * }$ , and the inequality can be strict. The feasible set $\{ k : D _ { k } \leq b \}$ is in general not downward closed: a feasible prefix may contain an infeasible shorter one.

Proof. $k _ { \mathrm { f v } }$ is feasible, so $k _ { \mathrm { f v } } \leq k ^ { * }$ . Example 1 gives $k _ { \mathrm { f v } } = 0 < k ^ { \ast } = 2$ with $k = 1$ infeasible. □

Proposition 3 (Magnitude budgets are suficient, not necessary). $\begin{array} { r } { \| S _ { k } \| \le \sum _ { j \le k } \| P _ { \pi _ { j } } \| } \end{array}$ . Hence every k with $\begin{array} { r } { \sum _ { j \leq k } \| P _ { \pi _ { j } } \| \leq b \| V _ { 0 } \| } \end{array}$ is feasible, and the largest such $k _ { \mathrm { m a g } }$ satisfies ${ \bar { k } } _ { \mathrm { m a g } } ^ { - } \leq k ^ { * }$

Two caveats keep these statements honest. First, $k ^ { * }$ is maximal among prefixes of the normascending order; it is not the largest subset with $\begin{array} { r } { \| \sum _ { i \in D } P _ { i } \| \le b \| V _ { 0 } \| } \end{array}$ , which is a combinatorial problem we do not solve. Second, because the feasible set is not downward closed, any postprocessing that shortens the dropped prefix (for instance, returning rows to the backward so that the number of kept rows is a multiple of a kernel tile) can break the budget unless the shorter prefix is itself re-checked; choosing among feasible prefixes only is safe.

Example 1 (Non-monotone distortion; constructed, not data). Take three candidates whose contributions, already in norm-ascending order, are $( 0 . 9 , 0 ) , ( - 1 , 0 )$ and (0, 2), and let the other rows contribute (0.1, 8), so $V _ { 0 } = ( 0 , 1 0 )$ . With $b = 0 . 0 5$ the absolute budget is 0.5. The prefix norms are $\left\| S _ { 0 } \right\| = 0 , \left\| S _ { 1 } \right\| = 0 . 9 ( \mathrm { v i o l a t e s } ) , \left\| S _ { 2 } \right\| = 0 . 1$ (feasible again), $\lVert S _ { 3 } \rVert \approx 2 . 0 0 2 5$ (violates). Firstviolation stopping keeps every candidate $( k = 0 )$ ; the full scan drops two $( k ^ { * } = 2 )$ . A magnitude budget would need $0 . 9 + 1 = 1 . 9 \leq 0 . 5$ for $k = 2$ and also selects $k = 0$

## 2.4 Weighted composition with an outer pruner

An outer per-epoch pruner such as InfoBatch [19] skips some rows before the forward and upweights others: rows whose stored loss is below the mean are skipped with probability r (we use $r = 0 . 5 )$ , and the surviving ones are weighted by $1 / ( 1 - r )$ . With the outer weights detached from diferentiation, the forwarded-batch objective is $\textstyle { \frac { 1 } { B } } \sum _ { i } w _ { i } \ell _ { i }$ , whose raw last-layer gradient is $\sum _ { i } w _ { i } P _ { i }$ The inner rule must therefore be applied to the weighted contributions $w _ { i } P _ { i }$ : order by $w _ { i } \| P _ { i } \|$ , use $\begin{array} { r } { V _ { 0 } ^ { w } = \sum _ { i } w _ { i } P _ { i } } \end{array}$ , and the Gram becomes $G _ { i j } ^ { w } = w _ { i } w _ { j } ( h _ { i } \cdot h _ { j } ) ( \phi _ { i } \cdot \phi _ { j } + 1 )$ . Proposition 1 then applies to the ideal weighted raw-gradient criterion; the practical implementation has the same epsilon and rounding qualifications. Each retained loss is weighted once, and $w \equiv 1$ recovers the unweighted mask. The unweighted rule carries no such guarantee:

Example 2 (Unweighted selection violates the budget; constructed). In one dimension, let candidate $a = + 0 . 3$ carry weight 2, candidate $c = - 0 . 3$ weight 1, and the other rows contribute $+ 3 . 0$ with weight 1; $b = 0 . 0 5$ . Unweighted, $\{ a , c \}$ sums to 0, so both are dropped. The applied gradient is $2 ( 0 . 3 ) - 0 . 3 + 3 . 0 = 3 . 3$ and the dropped part is 0.3, a relative change of $0 . 3 / 3 . 3 \approx 0 . 0 9 1 > 0 . 0 5$ Weighted, the order is $c \ ( 0 . 3 )$ , a (0.6); both prefixes have relative distortion $0 . 3 / 3 . 3 \approx 0 . 0 9 1$ , so $k ^ { * } = 0$

## 2.5 Re-weighting the dropped candidates

Deterministic dropping biases the update: the skipped part $S _ { k ^ { * } }$ ∗ is small at the last layer, but it is removed at every step. We evaluate four corrections applied to the dropped set $R = \{ \pi _ { 1 } , \ldots , \pi _ { k ^ { * } } \}$ ; all use only forward quantities.

• Uniform keep (rw). Keep each $i \in R$ with probability q and weight $1 / q \ ( q = 0 . 5 )$ . Conditional on R, the expected raw gradient equals the dense gradient for every layer before clipping or optimization; the expected back-propagated fraction is $1 - ( 1 - q ) k ^ { * } / B$ . The realised last-layer change is no longer bounded by b.

• Norm-proportional keep (rwp). Keep $i \in R$ with $p _ { i } = \mathrm { c l i p } ( \| P _ { i } \| / \tau , p _ { \mathrm { m i n } } , 1 )$ and weight $1 / p _ { i }$ with τ chosen numerically per batch to target mean probability q over $R \left( p _ { \mathrm { m i n } } = 0 . 0 5 \right.$ , so weights are at most 20). The mean is non-increasing in τ, so τ is found by a device-only grid bisection in log τ (4 rounds of 64 points); the target mean need not be attained exactly. Inverse-probability weighting remains unbiased for the raw gradient.

• Single rescale (det scale). When both norms are nonzero, drop R and multiply the kept rows’ losses by $c = \| V _ { 0 } \| / \| V _ { 0 } - S _ { k ^ { * } } \|$ , restoring the last-layer gradient norm. For ideal selection with $V _ { 0 } \neq 0$ and $b < 1 , c \in [ 1 / ( 1 + b ) , 1 / ( 1 - b ) ]$ by the triangle inequality.

• Last-layer fix (det lastfix). Drop R and add $S _ { k }$ ∗ (computable as $( H \odot m _ { R } ) ^ { \top } \tilde { \Phi } )$ to the final layer’s gradient after the backward, so, in exact arithmetic, the final layer receives the dense gradient and deeper layers the selected one.

## 3 Implementation

Numerical criterion. Algorithm 1 uses $\epsilon = 1 0 ^ { - 1 2 }$ and fp32 Gram arithmetic, clamping negative squared norms from roundof to zero. Ignoring rounding, its accepted prefix obeys $\left\| S _ { k } \right\| \le b ( \left\| V _ { 0 } \right\| +$ ϵ), rather than the ideal bound $b \Vert V _ { 0 } \Vert$ . For $V _ { 0 } \neq 0$ , the relative bound is $b ( 1 + \epsilon / \| V _ { 0 } \| )$ ; at $V _ { 0 } = 0$ the absolute allowance is bϵ. Finite-precision evaluation can add error, so this is not a numerically certified exact-b guarantee.

Factorised Gram. Since $P _ { a } \cdot P _ { b } = ( h _ { a } \cdot h _ { b } ) ( \tilde { \phi } _ { a } \cdot \tilde { \phi } _ { b } )$ , the Gram of the sorted candidates is $G = ( h _ { \pi } h _ { \pi } ^ { \top } ) \odot ( \phi _ { \pi } \phi _ { \pi } ^ { \top } + 1 )$ , and $\begin{array} { r } { \| S _ { k } \| ^ { 2 } = \sum _ { a , b \leq k } G _ { a b } } \end{array}$ is the k-th diagonal entry of the 2-D cumulative sum of G. All B + 1 prefix norms are obtained at once. Row norms and the denominator also factorise, $\| P _ { i } \| = \| h _ { i } \| \sqrt { \| \phi _ { i } \| ^ { 2 } + 1 }$ and $\begin{array} { r } { \| V _ { 0 } \| ^ { 2 } = \| h ^ { \top } \phi \| _ { F } ^ { 2 } + \| \sum _ { i } h _ { i } \| ^ { 2 } } \end{array}$ , so $P$ need never be formed. At $B = 1 2 8 , C = 1 0 0 , F = 5 1 2$ , the materialised P is about 25 MiB and its Gram about 1.7 GFLOP, whereas the factorised Gram needs two small matrix products $( B ^ { 2 } C$ and $B ^ { 2 } F$ multiply–adds). In the runs reported here the selector factorises the Gram (the dominant cost) and forms the row norms and denominator from $P ;$ a fully factorised variant gives the same mask in exact arithmetic. In fp32 the two forms round diferently and could flip a mask when some $D _ { k }$ lies within rounding of $b ;$ the masks were bitwise identical to the reference on 1000 of 1000 stored batches (at $b = 0 . 0 9$ and 0.25) and over 300 training steps.

No host synchronisation in the selector. Candidate masking, the sort (non-candidates get key +∞), the cumulative sums, the comparison with b and $k ^ { * } = \mathrm { m a x } _ { k } k [ k \leq | \mathcal { C } | ] [ D _ { k } \leq b ]$ are tensor operations; the drop mask stays on the device. Logged statistics are accumulated on the device and read once per epoch. The only remaining host read per step is the kept-row count that sizes the backward. On an RTX 5090 at a kept fraction of 0.69 the selector costs 0.12 ms per step, against 0.71 ms for the unfactorised Gram (of which 0.65 ms is the $B \times B ~ \mathrm { G E M M } )$ ; the factorised selector shortened the whole step by 5.4% [5.2, 5.6].

Execution requirement. Selecting rows does not by itself save time. If the rule is applied as a masked loss (dropped rows get zero loss weight), the backward still runs over all B rows. We therefore use a one-forward selective-backward execution that reuses the scoring forward’s activations and back-propagates only the kept rows, normalised by $B ;$ it targets the gradient of the selected objective in exact arithmetic. We checked the update against the masked-loss reference: the relative $L _ { 2 }$ diference was $1 . 5 \times 1 0 ^ { - 6 }$ in $\mathrm { f p 3 2 }$ (TF32 of) for the weighted composition. Under a cost model with forward = 1 and backward = 2 units, the ideal time ratio at kept fraction k is (1+2k)/3. Table 1 reports measured costs. On CIFAR-100 ResNet-18, the masked-loss execution of the same rule took $1 . 0 7 2 \times \ [ 1 . 0 6 9 , 1 . 0 7 5 ]$ the time of the activation-reusing execution at 200 epochs (1.054× at 120 epochs), with test accuracy diferences of −0.17 pp [-1.12, +0.78] and +0.41 pp [- 0.54, +1.36], which does not establish numerical trajectory equivalence. In the weighted InfoBatch composition the masked-loss version took 1.117× [1.116, 1.117] the time of the reusing execution and 1.016× [1.015, 1.018] the time of InfoBatch alone, i.e. no saving over InfoBatch despite backpropagating fewer rows. The remaining overhead over $( 1 + 2 k ) / 3$ is dominated by gathering the kept rows’ cached activations: 0.545 ms per step against a 0.542 ms memory-bandwidth roofline for the same bytes, suggesting limited benefit from scheduling changes alone for that measured gather.

## 4.4 Composition with InfoBatch

Setup. Same from-scratch recipe, seeds 2–6, InfoBatch with r = 0.5 and a full-data tail in the last 12.5% of epochs. ## 5 Related work

Per-step selection. Online batch selection [13] and Selective-Backprop [9] back-propagate highloss examples; importance sampling [10, 26] samples by (an upper bound on) the per-example gradient norm and re-weights to stay unbiased, and Katharopoulos and Fleuret [10] also use the gradient with respect to the network output as a cheap proxy. RHO-LOSS [14] selects by reducible held-out loss. VCAS [23] samples rows and tokens inside the backward with controlled variance. These methods use diferent selection or sampling objectives. CAPSkip evaluates the skipped set through its summed last-layer gradient, with an ideal deterministic bound rather than an unbiasedgradient claim. Closest to our setting, Balles et al. [2] select, within each forwarded batch of Selective-Backprop, a weighted subset whose last-layer gradient matches the batch mean, and report that neither this nor loss-based selection consistently beats a random subset; we include a matched random control for the same reason (§4). K-ABENA [3] excludes low-loss samples from the backward and keeps an unbiased estimate by inverse-probability re-weighting, which is related to our stochastic re-weighting variants (§2.5) rather than to the deterministic budget. For LLM fine-tuning, LOOM [4] selects, at every step, a non-negatively weighted subset of the batch that matches a leave-one-out gradient target in the optimizer’s metric; it reports that allowing signed (cancelling) weights lowered gradient error but hurt accuracy, whereas CAPSkip uses cancellation only to decide which rows to omit, with weight one on all kept rows.

Per-epoch pruning. InfoBatch [19] skips low-loss examples with probability r and rescales the rest, with a full-data tail; KAKURENBO [16] hides examples adaptively and adjusts the learning rate; RS2 [17] shows that repeated random subsets are a strong time-to-accuracy baseline. CAPSkip is complementary: it saves backward work on rows that were forwarded anyway, and §2.4 gives the form that keeps its bound when combined with such re-weighting pruners.

Gradient matching and coresets. CRAIG [15] and GRAD-MATCH [11] choose weighted subsets whose gradient sum approximates the full gradient, typically with last-layer gradient proxies and periodic re-selection. CAPSkip uses the same insight, that cancellation within the sum matters, in the reverse direction and at every step: it chooses what to omit so that the omitted sum is small, using exact last-layer gradients from the current forward rather than stale proxies. Lastlayer gradient embeddings $h _ { i } \otimes \ddot { \phi } _ { i }$ also appear in active learning [1], and score-based static pruning uses per-example gradient or error norms [5, 18]. LESSER [25] uses output-layer gradients, which need only a forward pass, as features for ranking post-training data by alignment with validation gradients; CAPSkip uses the same layer’s gradients online, within each batch, and through their sum rather than their individual alignment. The factorisation $\| P _ { i } \| = \| h _ { i } \| \| \tilde { \phi } _ { i } \|$ is the standard per-example gradient-norm trick for linear layers [7]; our use of the factorised Gram for all prefix norms at once is what makes the full scan cheap.

## 6 Limitations

• Evidence. The only approximately time-matched accuracy gain over dense training is one finetuning task with three seeds. From-scratch training resolves no time-to-accuracy diference, and the InfoBatch composition passes its bar in one of two experiments. We have not tested larger datasets, language models, or other optimisers.

• Scope of the guarantee. The ideal exact-arithmetic bound covers the raw final-afine-layer gradient at each step; the implementation is epsilon-relaxed and subject to rounding. It gives no control of deeper-layer gradients or of the trajectory; the accuracy drop at b = 1 (§4) shows that the last-layer budget does not by itself protect accuracy, and the deterministic last-layer corrections do not recover it.

• Maximality is relative to an order. k<sup>∗</sup> is the longest feasible prefix of the norm-ascending order, not the largest feasible subset.

• Execution and memory. Our activation-reusing execution saves time relative to masked-loss execution in the measured comparisons. This does not establish that reuse is necessary or superior to every alternative execution. Activation reuse costs memory (5078 vs. 4716 MiB peak in our fine-tuning runs) and a bandwidth-bound gather.

• Budget saturation. Candidates are limited to correctly classified rows, so the budget saturates and cannot reach low kept fractions; stochastic re-weighting trades the deterministic bound for unbiasedness.

• Hyper-parameters. b was tuned on validation in the from-scratch setting, and CAPSkip had more tuned configurations there than dense. The InfoBatch family was tuned separately, which is why we report comparisons against dense at the matched learning rate.

## 7 Conclusion

Measuring the summed, signed gradient of the examples one intends to skip, at the layer where it is exact, gives a selection rule with a simple per-step guarantee and an inexpensive on-device implementation. Its practical value depends on the workload and on an execution that turns skipped rows into skipped work: in our experiments it improves on approximately time-matched eager dense in one fine-tuning case, resolves no time-to-accuracy diference from scratch, and, in weighted form, composes with InfoBatch for a reproducible speed-up whose accuracy cost is not yet resolved.
